# F. 制度檔維護協議

> **本專案版本說明**：本檔原本位於 `%USERPROFILE%\.claude\ops\`，隨專案複製一份到 `docs/ops/`。
> 檔內出現的 `%USERPROFILE%\.claude\...` 路徑指的是**個人全域制度檔**的正本位置；
> 若是在本 repo 內改 `docs/ops/` 的副本，備份改為 `git` 本身（改動走 diff 即可，不必另外 `.bak`），
> 踩坑教訓寫進 `docs/ops/LESSONS.md`。兩邊出現分歧時，以全域正本為準，並把差異寫進 LESSONS。

對象：未來所有模型。目的：讓制度能安全演化，不會被一次錯誤更新毀掉，也不會無限膨脹。

## 1. 權限分級

**可以自行改（不必問使用者）**：
- 在 `LESSONS.md`（本目錄，不存在就建立）追加踩坑教訓。
- 修正查證後確認錯誤的**事實**（工具參數變了、路徑失效）——改之前必須先實際查證，並在改動處註記日期與證據來源。
- 更新 `A-diagnosis.md` 的「次要問題」清單。

**改之前必須先問使用者**：
- 刪除或反轉任何規則（例如放寬「驗證不自驗」）。
- 改動升降級路徑的門檻（dispatch.md §4 的次數）。
- 改動全域 `CLAUDE.md` 的「永遠生效的核心規則」（不論條數）。
- 改動本檔的權限分級本身。

**絕對不做**：
- 因為「這次不方便遵守」而修改規則——不方便就違規一次並記進 LESSONS.md，讓使用者裁決是否改制度。規則跟不上現實是使用者的裁決範圍，不是模型的。

## 2. 改檔流程（一律照做）

1. 備份：用 Bash 工具跑 `cp {檔} $HOME/.claude/backups/{檔名}.bak-{YYYYMMDD}`，或用 PowerShell 工具跑 `Copy-Item "{檔}" "%USERPROFILE%\.claude\backups\{檔名}.bak-{YYYYMMDD}"`（判準：你當下要用哪個 shell 工具就用對應版本——用 Bash 工具就跑 cp 版，用 PowerShell 工具就跑 Copy-Item 版；兩版路徑格式不同，不可互換）。
2. 動手改。
3. read-back 確認改動落地、沒破壞其他段落。
4. 在檔案底部的變更記錄（沒有就加一節）追加一行：`{日期} {模型} {改了什麼} {為什麼}`。

## 3. 踩坑教訓寫回哪裡、什麼格式

寫進 `%USERPROFILE%\.claude\ops\LESSONS.md`，每條固定格式：

```
## {YYYY-MM-DD} {一句話標題}
- 情境：{什麼任務、哪個專案}
- 坑：{發生什麼}
- 根因：{為什麼}
- 對策：{下次怎麼避免，寫成可執行判準}
- 應併入：{A-diagnosis / dispatch / judgment / templates / maintenance / 不併}
```

判斷「值得寫」的門檻：這個坑換一個模型還會踩＝寫；只是這次手滑＝不寫。

## 4. 精簡週期

- `LESSONS.md` 超過 **15 條** 或任一制度檔超過 **250 行** 時，觸發精簡：把重複條目合併、把已併入制度檔的條目刪除（制度檔才是正本，LESSONS 是收件匣）。
- 精簡是「改動規則」等級的操作 → 先備份，完成後在回覆裡告知使用者精簡了什麼。
- 每專案的 memory（`~/.claude/projects/{專案}/memory/`）維持既有機制，不要把全域制度寫進專案 memory，也不要把專案事實寫進 ops/。分界：**換個專案還成立的 → ops/；只對這個 repo 成立的 → 專案 memory 或專案 CLAUDE.md**。

## 5. 一致性檢查（每次改完制度檔做一次）

- [ ] 新規則與 CLAUDE.md 核心規則不衝突？
- [ ] 檔內引用的工具名/參數/路徑，這次有查證過還存在？
- [ ] 弱模型讀得懂？（有判準、有例子，沒有「保持高品質」式空話）
